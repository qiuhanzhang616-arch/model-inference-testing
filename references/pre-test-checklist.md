# 测试前问询清单

每个新测试先问。预填已知信息，用户不知道的技术项标为“待只读确认”。

## A. 测试目的

1. 测试类型是什么：功能、质量、性能、容量、稳定性、回归还是韧性？
2. 要回答的具体问题是什么？谁使用结果做什么决策？
3. 每类测试的通过值、失败值和不可退化项是什么？
4. 结果代表 POC、生产承诺、版本验收还是方向性研究？

## B. 被测对象

1. 模型/服务名称、Revision、量化/精度、Endpoint 和模型别名是什么？
2. Tokenizer/Processor、Chat Template、Adapter 和自定义代码是什么？
3. 平台、Region、硬件、卡数、节点、副本和并行拓扑是什么？
4. 框架、镜像摘要、驱动/工具链和实际进程参数是什么？
5. 对比对象是什么？除目标变量外是否同条件？

## C. 真实调用链

1. 客户端、SDK/Agent、企业鉴权、网关、负载均衡、Proxy 和模型 Endpoint 的完整顺序是什么？
2. 测试最短模型路径、真实业务路径还是两者？
3. 是否 Streaming；中间层是否缓冲或转换 Reasoning、Tool、JSON 或媒体？
4. 超时、重试、Fallback、连接复用和队列策略是什么？Benchmark 时是否禁用 Fallback？
5. 是否能用统一 Request ID 对齐客户端、网关和模型日志？

## D. 请求与数据

1. 给出真实请求样例、期望输出和成功定义。
2. 输入 P50/P95/最大值和单位是什么？输出分布和上限是什么？
3. Prompt、System、历史、Reasoning、Tools、Schema、Temperature、Seed、Stop 是否固定？
4. 图片/页/帧/音频的数量、分辨率、时长、Codec 和预处理是什么？
5. 数据是唯一、重复还是混合？期望缓存命中率是什么？
6. 数据是否敏感、是否允许保存请求/响应，脱敏规则是什么？

## E. 负载矩阵

1. 输入、输出、并发/QPS、模式的取值分别是什么？
2. Open-loop 到达率还是 Closed-loop 并发会话？突发模型是什么？
3. 每 Cell 请求数、持续时间、重复次数、超时和随机种子是什么？
4. 冷、热、缓存、混合和稳态如何定义？
5. 矩阵总格数、预计时长和优先顺序是什么？是否允许先筛选？

## F. 指标口径

1. 延迟从哪里开始、到哪里结束？首个可用输出是什么？
2. TTFT 是否包含 Reasoning；是否另算首个 Content？
3. TPOT、ITL、吞吐、QPS、并发、端到端时延的公式是什么？
4. 非文本任务使用 images/pages/frames/audio-seconds/s 还是 samples/s？
5. 成功、空响应、截断、超时、重试、取消和 Fallback 如何计数？
6. 报告 P50/P95/P99/最大、平均还是完整分布？

## G. 质量判定

1. 使用什么数据集或 Benchmark，版本和样本范围是什么？
2. 正确性由单元测试、标签、Recall/Precision、Schema、Judge、人评或媒体指标判断？
3. 是否需要 Tool Calling、代码执行、引用、长上下文检索或结构化输出专项？
4. 性能测试后是否必须重复质量/功能回归？

## H. 资源与观测

1. 测试机位置、CPU/网络和客户端并发能力是否足够？
2. 是否能采集模型、每实例/Rank、队列、缓存、显存/HBM、利用率、通信、CPU、网络和存储？
3. 是否有背景业务流量；测试窗口能否独占？
4. 是否允许 Profiler，允许的性能开销是多少？

## I. 安全与授权

1. 最大并发/QPS、时长、请求数、费用和资源上限是什么？
2. 哪些错误必须立即停止？恢复观察多久？
3. 是否允许读取日志、保存结果、发送敏感样本和使用公网？
4. 若需要切换配置版本，是否已批准变更、重启和回退？
5. 谁确认正式开始和最终验收？

## 开始前确认块

- 测试问题和通过标准；
- 被测版本与可比基线；
- 路径、请求语义和数据权限；
- 完整矩阵、格数、重复和预计时长；
- 指标公式及失败计数；
- 质量判定；
- 监控和原始数据位置；
- 最大负载、停止条件与恢复要求；
- 未决风险与授权状态。

用户确认后再运行正式测试。
