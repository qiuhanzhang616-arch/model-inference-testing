# ModelArts 调优前问询清单

这是新项目调优的强制入口。先从用户提供的文件、当前对话和只读环境证据中填写；只追问缺失或冲突项。不得要求用户提供明文密码、API key、Cookie、私钥或 OTP，可询问凭据引用或已登录入口。

不要用一条长消息机械重复全部问题。按“业务与目标 → 负载与数据 → 环境与权限 → 测试和交付”分组询问；如果某组答案已经明确，直接复述确认。

## A. 业务场景和质量

1. 这次模型承担什么业务任务？请给 1–3 个真实请求示例和期望输出。
2. 输入属于单图、多图、视频、文档页、图文多轮还是混合？一次请求包含多少 work item？
3. 输出是分类、检测框、文本生成、问答、embedding、JSON/其他结构化协议，还是工具调用？是否流式返回？
4. 什么算业务成功？使用准确率、召回率、F1、字段准确率、JSON 有效率、人工验收或其他质量门槛？
5. 哪些错误不可接受？例如漏检、幻觉、截断、格式错误、字段缺失、超时或重复结果。

## B. 性能目标和优先级

6. 优先优化吞吐、首包延迟、整请求延迟、decode TPS、资源成本，还是在多个指标间权衡？请排序。
7. 明确目标值和统计口径：requests/s、work items/s、output tokens/s、TTFT、P50/P95/P99、最大延迟、成功率。
8. 是否有“总量/完成时限”目标？若有，给出总 work item 数、时限、峰值系数和期望安全余量。
9. 性能和质量发生冲突时，哪一项是硬门槛？允许的最大质量退化是多少？

## C. 输入和输出分布

10. 代表性数据集在哪里？样本数量、数据类型、语言、长尾和敏感数据限制是什么？
11. 输入规模的 P50/P95/最大值是什么？按场景填写分辨率、图片数、页数、视频时长/帧数、文本 token 或视觉 token。
12. 输入是否大量重复或共享前缀？生产中的真实复用率是多少？要测冷、热、混合还是全部？
13. prompt、chat template、system message 和输出 schema 是否已冻结？由谁确认变更？
14. thinking、temperature、top_p、工具调用、约束解码、`max_tokens`/自然输出策略分别是什么？
15. 是否允许客户端预处理变化，例如缩放、裁剪、压缩、抽帧或批图？哪些业务规格绝对不能变？

## D. 流量和压测模型

16. 生产是闭环并发、固定到达率、突发流量还是离线批处理？
17. 当前和目标并发/到达率范围是什么？需要展开哪些具体档位？
18. 每格请求数、重复次数、预热次数、超时和重试规则是什么？
19. 要区分 cold start、cold cache、warm cache、稳态和持续运行测试吗？各自持续多久？
20. 压测从哪里发起，走直连、API Gateway、LiteLLM 还是业务入口？是否允许诊断性直连？
21. 是否存在网关 retry、fallback、响应缓存、限流或负载均衡？正式成绩是否必须包含这些层？

## E. 模型、软件和硬件

22. 精确模型名、权重 revision、量化方式、模型来源和许可证是什么？
23. 使用 vLLM-Ascend、SGLang、MindIE 或其他框架？镜像、框架、CANN、驱动版本是什么？
24. ModelArts Standard 的账号/Region、服务、部署和当前版本是什么？哪些是生产或受保护服务？
25. NPU 型号、总卡数、当前 TP/DP/EP/PD 拓扑是什么？卡数是否固定，允许测试哪些拓扑？
26. 当前上下文窗口、batch/seq、显存利用率、缓存、调度和 CPU worker 参数是什么？
27. 当前是否已有可复现基线、原始日志、资源采集和已知失败配置？

## F. 授权、风险和回退

28. 本次允许修改哪些参数、服务和路由？是否允许重建版本、切流、重启或停机？
29. 允许的维护窗口、最长停机、最大测试时长和资源成本边界是什么？
30. 当前稳定版本和回退方式是什么？回退后需要验证哪些健康项？
31. 哪些服务不得触碰？是否存在同时运行的其他压测或生产流量？
32. 发生 OOM、EngineDead、错误率、延迟或费用达到什么条件时必须停止？

## G. 观测和交付

33. 能采集哪些指标：请求事件、TTFT/TPOT、队列、running/waiting、NPU 利用率、HBM、CPU、内存、网络、HCCL、缓存计数？
34. 原始数据、脚本、manifest、图表和报告保存在哪里？是否需要 SFS、OBS、Obsidian、Excel、Word 或其他格式？
35. 谁负责确认质量和最终候选？是否需要客户签字或正式验收报告？

## 向用户回显的确认摘要

正式执行前，用以下结构回显，不要只说“参数已确认”：

```text
业务场景：
工作项定义：
输入分布：
输出与质量门槛：
性能目标与单位：
模型/量化/框架：
硬件与拓扑约束：
服务与访问路径：
缓存和流量模式：
主测试矩阵：
预热/重复/预计时长：
允许的变更：
停止条件：
回退版本：
原始数据与报告位置：
仍待确认：
```

只有会改变实验设计或扩大授权范围的未知项才阻塞执行。可从环境只读验证的事实优先自行核对，不把调查工作推回给用户。
