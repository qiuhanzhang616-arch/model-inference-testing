# 文档、票据与证件识别分支

仅当业务明确属于文档 OCR、票据/表单抽取、证件识别、文档 NER 或 JSON 字段结构化时加载。本分支是在通用问询和通用调优流程上的增量，不覆盖用户已确认条件。

## 额外必问

- 文档类型有哪些：身份证件、护照、医疗材料、发票、合同、表单或其他？各类型占比是多少？
- 一次请求是一页、一份多页文档还是多份文档？页数 P50/P95/最大值是多少？
- 图片来源是扫描件、手机拍照、截图还是 PDF 渲染？分辨率、方向、透视、模糊、反光和压缩分布是什么？
- 是否包含手写、印章、表格、多栏、二维码、签名或遮挡？
- 语言、地区格式、日期/金额/证件号规则是什么？
- 输出字段、类型、必填/可空、数组、枚举、嵌套关系和 `additionalProperties` 要求是什么？
- OCR 文本、NER 实体和最终 JSON 分别如何判分？字段级 exact match、规范化规则、召回率和 JSON 有效率门槛是多少？
- 是否允许旋转、去畸变、裁剪、增强、压缩和最长边缩放？客户验收使用原图还是预处理图？
- 生产数据是否多数唯一？是否允许用不改变解码像素的方式构造媒体 cache miss？
- 文档是否包含个人敏感信息？压测数据、日志和模型输出的留存与脱敏要求是什么？

## 基准数据分层

代表性数据集至少按以下维度分层，不能只挑清晰样本：

- 文档类型和语言。
- 单页与多页。
- 清晰、模糊、旋转、透视、反光、遮挡。
- 打印、手写、表格和印章。
- 输入尺寸或视觉 token 的 P50/P95/最大值。
- 短输出和长输出、简单字段和数组/嵌套字段。

性能集和质量集可以不同，但必须固定 manifest。若为了 cache-bust 修改媒体字节，先证明解码像素和质量判分不变。

## 请求与输出校验

- 一次请求的页数和图片数以真实 API 协议为准，不默认“一图一请求”。
- 固定图片/PDF 预处理版本、JPEG 质量、MIME、Base64 或对象存储 URL 方式。
- 结构化输出应校验 JSON 可解析、schema、必填字段、字段类型、额外字段和 finish reason。
- 对截断或非法 JSON 的重试策略必须固定；报告同时给出首轮有效率、最终有效率和重试开销。
- `max_tokens` 从真实完成长度分布推导，并给 JSON 闭合留余量；缩短到出现截断的候选不得晋升。

## 专项调优变量

### 视觉预处理

分别测试并记录原图、最长边缩放、分块/切片、旋转校正和 PDF 渲染 DPI。只有客户允许的预处理才能进入最终候选；较低分辨率的探索成绩不得冒充验收成绩。

### 多模态处理器缓存

重复模板、重复页面和唯一文档的缓存收益可能完全不同。至少区分：

- 重复媒体热缓存诊断。
- 唯一媒体或 cache-miss 稳态测试。
- 接近生产复用率的混合测试。

观察连续正式轮次的尾延迟，识别缓存填充和 LRU 淘汰漂移。processor cache、prefix/KV cache 和网关响应缓存分开记录。

### 输出与约束解码

比较自然 JSON、JSON Schema/grammar 等当前框架实际支持的模式时，保持字段语义和质量判定不变。记录约束解码初始化、CPU 开销、生成 token、截断和无效 JSON；不能只看模型 decode TPS。

## 本分支至少报告

- documents/s、pages/s 和 requests/s 中适合当前协议的指标。
- 首轮及最终 JSON 有效率、字段级质量、重试率。
- 按文档难度/类型分层的质量和延迟。
- 预处理时间、服务端总延迟、P50/P95/最大延迟。
- 唯一、重复和混合缓存条件的独立成绩。
- 图片/页数/输出上限发生变化时的不可比说明。
